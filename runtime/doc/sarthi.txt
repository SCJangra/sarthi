==============================================================================
Introduction                                                      *sarthi-intro*

Sarthi sets `vim.g.sarthi`, so a config or plugin shared with the TUI can
check it before using what only Sarthi has. Fonts are Neovim's own `'guifont'`
and `'linespace'` options.

==============================================================================
Settings                                                       *sarthi-settings*

Set with `require('sarthi').setup({ … })`, by section, e.g.

>lua
    require('sarthi').setup({
      window = {
        shadow = { opacity = 0.5 },
        outline = { enabled = true, highlight = 'Comment' },
      },
      background = { opacity = 0.9 },
    })
<
Each section and key is optional: what isn't given has its default. `setup()`
can be called again, e.g. from a keymap, and applies at once; each call
replaces what the last one gave, so what it leaves out is back to its default.
A mistake is an error at the call, and keeps the settings as they were.

Each key says whether a window can have its own value of it too (Per-window
settings |sarthi-w:sarthi|): "global, or per window" if it can, "global only"
if not.

------------------------------------------------------------------------------
Per-window settings                                            *sarthi-w:sarthi*

The sections of the settings' `window` (`scroll_animation`, `shadow`,
`outline`, `rounded_corners`, `padding`) can be set for one window too, in its
`w:sarthi` table: the same sections with the same keys, but
`exclude_filetypes`. Each key given is the window's, whatever the setting's;
only the filetypes a setting excludes win over it: such a window never has
that effect, even with `enabled = true`.

>lua
    vim.w[win].sarthi = { outline = { enabled = true, width = 2 } }
<
For a key it doesn't give, a window has the setting's `scroll_animation` and
`shadow` (every window scrolls, and every floating and external window casts a
shadow). `outline`, `rounded_corners` and `padding` are only ever around
external windows: Neovim places floating windows in its cells, without room
for them. The settings' are for windows whose `w:sarthi` has `managed = true`;
others have them only if their `w:sarthi` turns them on, with the defaults for
the keys it doesn't give.

>lua
    vim.w[win].sarthi = { managed = true, padding = { size = 2 } }
<
The window functions |sarthi.api| set it from the `sarthi` table of a window's
config, marked `managed`. A mistake in a table set directly is shown once, and
the window gets nothing of its own until it's fixed.

cursor_animation                                       *sarthi-cursor_animation*

How the cursor moves to a new place: its corners each on their way, the
leading ones faster, so it stretches towards where it goes and shrinks back as
it arrives

cursor_animation.enabled                       *sarthi-cursor_animation.enabled*

`boolean`, default `true` · global only

Whether the cursor moves to its new place, or jumps there

cursor_animation.curve                           *sarthi-cursor_animation.curve*

`sarthi.Animation`, default
`{ type = "spring", stiffness = 700, damping = 53 }` · global only

How it moves to its new place

cursor_animation.trail                           *sarthi-cursor_animation.trail*

`number`, default `1` · global only

How much the trailing corners lag behind the leading ones: from 0, where the
cursor moves as it is, to 1, where its leading edge is there at once

cursor_animation.overrides                   *sarthi-cursor_animation.overrides*

`sarthi.CursorOverride[]`, default

Other values for some moves (overrides |sarthi.CursorOverride|): each one that
applies to a move in place of `curve` and `trail`, later ones winning. By

background                                                   *sarthi-background*

The editor's background in the OS window: how see-through it is, and whether
the desktop behind it is blurred

background.opacity                                   *sarthi-background.opacity*

`number`, default `1` · global only

How opaque the editor's background is, from 0 to 1. Text, highlighted
backgrounds and floating windows stay opaque. Needs a compositor that shows
windows' transparency; on X11, a compositing window manager, and even then
some GPU drivers can't. Sarthi warns when it can't show it.

background.blur                                         *sarthi-background.blur*

`boolean`, default `false` · global only

Whether the desktop behind a see-through background is blurred. The compositor
does it, where it can (e.g. KDE Plasma, macOS); elsewhere the background is
only see-through. Never on X11, where Sarthi warns about it.

Animations                                                    *sarthi.Animation*

An animation's curve,
e.g. `{ type = "spring", stiffness = 400, damping = 32 }`. Durations are in
milliseconds; a value left out has its default.

type = "none"                                            *sarthi.Animation.none*

No animation: it's in its new place at once

type = "spring"                                        *sarthi.Animation.spring*

Like a weight on a spring: pulled by `stiffness`, slowed by `damping`. With
less damping than 2 × √stiffness it overshoots and bounces back.

- `stiffness`: `number`, default `400`. How hard the spring pulls
- `damping`: `number`, default `32`. How much the spring slows it down

type = "linear"                                        *sarthi.Animation.linear*

At an even speed over `duration`

- `duration`: `number`, default `150`. How long it takes, in milliseconds

type = "ease_out"                                    *sarthi.Animation.ease_out*

Fast at first, then slowing down, over `duration`

- `duration`: `number`, default `150`. How long it takes, in milliseconds

type = "ease_in_out"                              *sarthi.Animation.ease_in_out*

Speeding up, then slowing down, over `duration`

- `duration`: `number`, default `150`. How long it takes, in milliseconds

type = "cubic_bezier"                            *sarthi.Animation.cubic_bezier*

Like CSS's `cubic-bezier()` over `duration`

- `points`: `number[]`, required. The curve's control points: x1, y1, x2, y2,
  with the x values from 0 to 1, e.g. `{ 0.25, 0.1, 0.25, 1 }`
- `duration`: `number`, default `150`. How long it takes, in milliseconds

Lua module                                                              *sarthi*

`require('sarthi')`, for your config: `require('sarthi').setup({ … })`. Only
Sarthi has the module, so a config shared with the TUI checks `vim.g.sarthi`,
which Sarthi sets, first.

sarthi.setup({settings})                                          *sarthi.setup*

Sets Sarthi's settings: those given, and the defaults of the rest, in place of
what an earlier call gave. Applies at once, so it can be called again later,
e.g. from a keymap. A mistake is an error at the call.

Parameters:

- `{settings}` (`sarthi.Settings?`): The settings (Settings
  |sarthi-settings|); left out, all the defaults

sarthi.settings()                                              *sarthi.settings*

The settings in effect: those given to `setup()`, and the defaults of the
rest, e.g. to place a window past another's padding when it has the user's. A
copy: changing it changes nothing.

Returns: `sarthi.Settings`

sarthi.set_font_size({points})                            *sarthi.set_font_size*

Sets the font size, in points (4 to 96), by setting `:h` in `guifont`.

Parameters:

- `{points}` (`number`): Size in points

sarthi.change_font_size({delta})                       *sarthi.change_font_size*

Makes the font `delta` points bigger, or smaller if negative, by setting `:h`
in `guifont`. The size stays within 4 to 96 points.

Parameters:

- `{delta}` (`number`): Points to add, or to take away if negative

sarthi.reset_font_size()                                *sarthi.reset_font_size*

Sets `guifont` back to its value before the font size was first changed,
unless it was set otherwise since.

Window functions                                                    *sarthi.api*

`require('sarthi').api`: Neovim's window functions that take a window config,
taking a `sarthi` table in it too, for what only Sarthi does with windows.
Everything else is `vim.api`. Only Sarthi has the module, so a plugin shared
with the TUI checks `vim.g.sarthi` first, and opens its window another way
otherwise.

>lua
    require('sarthi').api.nvim_open_win(buf, false, {
      external = true, width = 40, height = 30,
      sarthi = {
        place = { relative = 'editor', row = 2, col = 4 },
        shadow = { opacity = 0.6 },
      },
    })
<
The `sarthi` table (`WindowConfig` |sarthi.WindowConfig|) takes the window's
own values of the sections of the settings' `window`, with the same keys
(Settings |sarthi-settings|), each in place of the setting's; for those it
doesn't give, the settings'. `shadow` and `scroll_animation` apply to any
window; `outline`, `rounded_corners` and `padding` only to external windows
(`external = true`), as do `place` and `font`. The values are kept in the
window's `w:sarthi`, marked `managed`, which a plugin can also set itself
(Per-window settings |sarthi-w:sarthi|).

sarthi.api.nvim_open_win({buf}, {enter}, {config})    *sarthi.api.nvim_open_win*

Like `vim.api.nvim_open_win()`, with a `sarthi` table in `config`
(`WindowConfig` |sarthi.WindowConfig|). Managed even without one: it has the
settings' outline, corners and padding. A mistake in the `sarthi` table closes
the window again, so the call does nothing but fail.

Parameters:

- `{buf}` (`integer`): The buffer it shows
- `{enter}` (`boolean`): Whether it becomes the current window
- `{config}` (`vim.api.keyset.win_config|{ sarthi?: sarthi.WindowConfig }`):
  Neovim's window config, with a `sarthi` table in it

Returns: `integer`

sarthi.api.nvim_win_set_config({win}, {config}) *sarthi.api.nvim_win_set_config*

Like `vim.api.nvim_win_set_config()`, with a `sarthi` table in `config`: what
it gives replaces what was given before, key by key, and a section's values
key by key too.

Parameters:

- `{win}` (`integer`): The window, or 0 for the current one
- `{config}` (`vim.api.keyset.win_config|{ sarthi?: sarthi.WindowConfig }`):
  Neovim's window config, with a `sarthi` table in it

sarthi.api.nvim_win_get_config({win})           *sarthi.api.nvim_win_get_config*

Like `vim.api.nvim_win_get_config()`, with the window's `sarthi` table: its
`w:sarthi`, and what else was given.

Parameters:

- `{win}` (`integer`): The window, or 0 for the current one

Returns: `vim.api.keyset.win_config|{ sarthi?: sarthi.WindowConfig }`

sarthi.place                                                *sarthi.WindowPlace*

Where Sarthi places an external window, over Neovim's screen (`sarthi.place`).

`{ center = true }` centers it, as it is until placed; otherwise it's placed
like a floating window, with its `anchor` corner at `row`, `col` of what it's
`relative` to. Like a floating window with a border, whose frame, its padding
and outline (padding |sarthi-window.padding|, outline
|sarthi-window.outline|), takes the border's place: the frame's `anchor`
corner is at `row`, `col`, and the window's cells are inside it. `row` and
`col` are whole cells, a fraction dropped. A window it's relative to counts
from its text, inside its frame, border and winbar, like Neovim's floats do.
Like those, it's kept on the screen with its frame, above the command line,
and with `fixed` not moved sideways unless anchored on the right. `offset`
moves it further by logical pixels.

place.center                                         *sarthi.WindowPlace.center*

`boolean`

Centered over the screen

place.relative                                     *sarthi.WindowPlace.relative*

`"editor"|"win"|"cursor"`

What `row` and `col` count from

place.win                                               *sarthi.WindowPlace.win*

`integer`

The window it's relative to, for `relative = 'win'`; the current window if
left out, like for floats

place.anchor                                         *sarthi.WindowPlace.anchor*

`"NW"|"NE"|"SW"|"SE"`

The corner at `row`, `col`

place.row                                               *sarthi.WindowPlace.row*

`number`

Rows from what it's relative to

place.col                                               *sarthi.WindowPlace.col*

`number`

Columns from what it's relative to

place.offset                                         *sarthi.WindowPlace.offset*

`sarthi.PlaceOffset`

Moves it further, in logical pixels, e.g. past another window's padding:
`{ x = …, y = … }`

place.fixed                                           *sarthi.WindowPlace.fixed*

`boolean`

Not moved sideways to stay on the screen, unless anchored on the right, like a
float's `fixed`
