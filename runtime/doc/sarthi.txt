INTRODUCTION                                                    *sarthi-intro*

Sarthi sets `vim.g.sarthi`, so a config or plugin shared with the TUI can
check it before using what only Sarthi has. Fonts are Neovim's own
'guifont' and 'linespace' options.

==============================================================================
SETTINGS                                                     *sarthi-settings*

Set with `require('sarthi').setup({ … })`, by section, e.g.
>lua
    require('sarthi').setup({
      shadow = { opacity = 0.5 },
      outline = { enabled = true, highlight = 'Comment' },
    })
<
Each section and key is optional: what isn't given has its default.
setup() can be called again, e.g. from a keymap, and applies at once; each
call replaces what the last one gave, so what it leaves out is back to its
default. A mistake is an error at the call, and keeps the settings as they
were.

PER-WINDOW SETTINGS                                          *sarthi-w:sarthi*

The sections about a window (`scroll`, `shadow`, `outline`, `corners`,
`padding`) can be set for one window too, in its `w:sarthi` table: the same
sections with the same keys, but `exclude_filetypes`. Each key given is the
window's, whatever the setting's; only the filetypes a setting excludes win
over it: such a window never has that effect, even with `enabled = true`.
>lua
    vim.w[win].sarthi = { outline = { enabled = true, width = 2 } }
<
For a key it doesn't give, a window has the setting's `scroll` and `shadow`
(every window scrolls, and every floating and external window casts a
shadow). `outline`, `corners` and `padding` are only ever around external
windows: Neovim places floating windows in its cells, without room for them.
The settings' are for windows whose `w:sarthi` has `managed = true`; others
have them only if their `w:sarthi` turns them on, with the defaults for the
keys it doesn't give.
>lua
    vim.w[win].sarthi = { managed = true, padding = { size = 2 } }
<
|sarthi.api| sets it from the `sarthi` table of a window's config, marked
`managed`. A mistake in a table set directly is shown once, and the window
gets nothing of its own until it's fixed.

SCROLL                                                         *sarthi-scroll*

How text that scrolled moves to its new place

Per window too, in `w:sarthi.scroll` or `sarthi.scroll` (|sarthi.api|):
`enabled`, `animation`. Each is the window's, whatever the setting's, but
`exclude_filetypes` wins over a window's `enabled`.

scroll.enabled                                         *sarthi-scroll.enabled*
    Type: boolean
    Default: `true`
    Whether text that scrolled slides to its new place, or jumps there

scroll.animation                                     *sarthi-scroll.animation*
    Type: |sarthi-animation|
    Default: `{ curve = 'spring', stiffness = 400, damping = 32 }`
    How it moves to its new place

scroll.exclude_filetypes                     *sarthi-scroll.exclude_filetypes*
    Type: string[]
    Default: `{}`
    Windows showing these filetypes jump to their new place, e.g. menus whose
    selected line is highlighted text, whatever their `w:sarthi` gives. Glob
    patterns, e.g. `cmp_*`.

CURSOR                                                         *sarthi-cursor*

How the cursor moves to a new place: its corners each on their way, the
leading ones faster, so it stretches towards where it goes and shrinks back as
it arrives

cursor.animation                                     *sarthi-cursor.animation*
    Type: |sarthi-animation|
    Default: `{ curve = 'spring', stiffness = 700, damping = 53 }`
    For moves farther than a couple of cells along a row

cursor.short_animation                         *sarthi-cursor.short_animation*
    Type: |sarthi-animation|
    Default: `{ curve = 'ease_out', duration = 40 }`
    For short moves along a row, like typing

cursor.trail                                             *sarthi-cursor.trail*
    Type: number
    Default: `0.7`
    How much the trailing corners lag behind the leading ones: from 0, where
    the cursor moves as it is, to 1, where its leading edge is there at once

cursor.animate_insert_mode                 *sarthi-cursor.animate_insert_mode*
    Type: boolean
    Default: `true`
    Whether moves in insert and replace mode animate, e.g. while typing

cursor.animate_cmdline                         *sarthi-cursor.animate_cmdline*
    Type: boolean
    Default: `true`
    Whether moves into and out of the command line animate

The shadow under floating and external windows, in logical pixels

Per window too, in `w:sarthi.shadow` or `sarthi.shadow` (|sarthi.api|):

shadow.enabled                                         *sarthi-shadow.enabled*
    Type: boolean
    Default: `true`
    Whether windows cast one

shadow.blur                                               *sarthi-shadow.blur*
    Type: number
    Default: `16`

shadow.offset                                           *sarthi-shadow.offset*
    Type: { number, number }
    Default: `{ 0, 4 }`
    How far the shadow is moved from the window: right and down, or left and

shadow.opacity                                         *sarthi-shadow.opacity*
    Type: number
    Default: `0.3`

shadow.exclude_filetypes                     *sarthi-shadow.exclude_filetypes*

OUTLINE                                                       *sarthi-outline*

A line around external windows, just outside them, in logical pixels: not
floating windows, which Neovim places without room for it. For windows whose
`w:sarthi` is `managed`, e.g. opened with |sarthi.api|; others have one only
if their `w:sarthi` turns it on.

Per window too, in `w:sarthi.outline` or `sarthi.outline` (|sarthi.api|):
`enabled`, `width`, `highlight`. Each is the window's, whatever the setting's,
but `exclude_filetypes` wins over a window's `enabled`.

outline.enabled                                       *sarthi-outline.enabled*
    Type: boolean
    Default: `false`
    Whether windows have one. Off by default: a window with a border of its
    own (`nvim_open_win()`'s `border`) would have two.

outline.width                                           *sarthi-outline.width*
    Type: number
    Default: `1`
    How thick the line is

outline.highlight                                   *sarthi-outline.highlight*
    Type: string
    Default: `'FloatBorder'`
    The highlight group whose text color the line has

outline.exclude_filetypes                   *sarthi-outline.exclude_filetypes*
    Type: string[]
    Default: `{}`
    Windows showing these filetypes have no outline, whatever their `w:sarthi`
    gives. Glob patterns, e.g. `cmp_*`.

CORNERS                                                       *sarthi-corners*

Rounded corners of external windows, in logical pixels: not floating windows,
whose text would be cut by them. The outline follows them. For windows whose
`w:sarthi` is `managed`, e.g. opened with |sarthi.api|; others have them only
if their `w:sarthi` turns them on.

Per window too, in `w:sarthi.corners` or `sarthi.corners` (|sarthi.api|):
`enabled`, `radius`. Each is the window's, whatever the setting's, but
`exclude_filetypes` wins over a window's `enabled`.

corners.enabled                                       *sarthi-corners.enabled*
    Type: boolean
    Default: `false`
    Whether windows have them. Off by default: a window's text in its corner
    cells isn't cut to them.

corners.radius                                         *sarthi-corners.radius*
    Type: number
    Default: `8`

corners.exclude_filetypes                   *sarthi-corners.exclude_filetypes*
    Type: string[]
    Default: `{}`
    Windows showing these filetypes keep square corners, whatever their
    `w:sarthi` gives. Glob patterns, e.g. `cmp_*`.

Per window too, in `w:sarthi.padding` or `sarthi.padding` (|sarthi.api|):

padding.enabled                                       *sarthi-padding.enabled*

ANIMATIONS                                                  *sarthi-animation*

An animation is a table with its `curve` and that curve's values, in
milliseconds for durations. A value left out has the default shown.

'none'                                                 *sarthi-animation-none*
    `{ curve = 'none' }`
    No animation: it's in its new place at once.

'spring'                                             *sarthi-animation-spring*
    `{ curve = 'spring' }`
    Defaults: `stiffness = 400, damping = 32`
    Like a weight on a spring: pulled by `stiffness`, slowed by `damping`.
    With less damping than 2 × √stiffness it overshoots and bounces back.

'linear'                                             *sarthi-animation-linear*
    `{ curve = 'linear' }`
    Defaults: `duration = 150`
    At an even speed over `duration`

'ease_out'                                         *sarthi-animation-ease_out*
    `{ curve = 'ease_out' }`
    Defaults: `duration = 150`
    Fast at first, then slowing down, over `duration`

'ease_in_out'                                   *sarthi-animation-ease_in_out*
    `{ curve = 'ease_in_out' }`
    Defaults: `duration = 150`
    Speeding up, then slowing down, over `duration`

'cubic_bezier'                                 *sarthi-animation-cubic_bezier*
    `{ curve = 'cubic_bezier', points = { 0.25, 0.1, 0.25, 1 } }`
    Defaults: `duration = 150`
    Like CSS's `cubic-bezier()` over `duration`: `points` are x1, y1, x2, y2,
    with the x values from 0 to 1.

Lua module                                                            *sarthi*

`require("sarthi")`, for your config: `require("sarthi").setup({ … })`. Only
Sarthi has the module, so a config shared with the TUI checks `vim.g.sarthi`,
which Sarthi sets, first.

sarthi.setup({opts?})                                           *sarthi.setup*
    Sets Sarthi's settings: those given, and the defaults of the rest, in place
    of what an earlier call gave. Applies at once, so it can be called again
    later, e.g. from a keymap. A mistake is an error at the call.

    Parameters: ~
        {opts?}  (table) The settings (see |sarthi-settings|)


sarthi.settings()                                            *sarthi.settings*
    The settings in effect: those given to `setup()`, and the defaults of the
    rest (|sarthi-settings|), e.g. to place a window past another's padding
    when it has the user's. A copy: changing it changes nothing.

    Returns: ~
        (table)


sarthi.set_font_size({points})                          *sarthi.set_font_size*
    Sets the font size, in points (4 to 96), by setting `:h` in `guifont`.

    Parameters: ~
        {points}  (number) Size in points


sarthi.change_font_size({delta})                     *sarthi.change_font_size*
    Makes the font `delta` points bigger, or smaller if negative, by setting
    `:h` in `guifont`. The size stays within 4 to 96 points.

    Parameters: ~
        {delta}  (number) Points to add


sarthi.reset_font_size()                              *sarthi.reset_font_size*
    Sets `guifont` back to its value before the font size was first changed,
    unless it was set otherwise since.

Window functions                                                  *sarthi.api*

`require("sarthi").api`: Neovim's window functions that take a window config,
taking a `sarthi` table in it too, for what only Sarthi does with windows.
Everything else is `vim.api`. Only Sarthi has the module, so a plugin shared
with the TUI checks `vim.g.sarthi` first, and opens its window another way
otherwise.
>lua
  require('sarthi').api.nvim_open_win(buf, false, {
    external = true, width = 40, height = 30,
    sarthi = {
      place = { relative = 'editor', row = 2, col = 4 },
      shadow = { opacity = 0.6 },
    },
  })
<
The `sarthi` table (|sarthi.WindowConfig|) takes the window's own values of
the settings' sections about a window, with the same keys
(|sarthi-settings|), each in place of the setting's; for those it doesn't
give, the settings'. `shadow` and `scroll` apply to any window; `outline`,
`corners` and `padding` only to external windows (`external = true`), as
do `place` and `font`. The values are kept in the window's `w:sarthi`,
marked `managed`, which a plugin can also set itself (|sarthi-w:sarthi|).

sarthi.WindowPlace                                        *sarthi.WindowPlace*
    Where Sarthi places an external window, over Neovim's screen: `{ center =
    true }` centers it, as it is until placed; otherwise it's placed like a
    floating window, with its `anchor` corner at `row`, `col` of what it's
    `relative` to.

    A window's frame, its padding and outline (|sarthi-padding|,
    |sarthi-outline|), is in pixels around its cells, so it goes around
    where the window is placed: the frame starts at the anchor point, and
    the cells move away from it by the frame's width. Relative to a window,
    `row` and `col` count in its cells from where its frame starts, not its
    text, unlike from inside a Neovim `border`. So windows line up in whole
    cells whatever their frames: `col = 0` lines up with the window's left
    edge, and `row` = its height starts just below it. Floating windows
    placed by Neovim go the same. To go past a frame, e.g. the window's
    padding, `offset` moves it further by pixels: `{ y = 16 }` is just below
    a window with 8 pixels of padding above and below its text.

    Fields: ~
        {center?}    (boolean) Center it
        {relative?}  ("editor"|"win"|"cursor") What it's placed relative to
        {win?}       (integer) For 'win': the window, or the current one
        {anchor?}    ("NW"|"NE"|"SW"|"SE") Its corner at `row`, `col`
        {row?}       (number) Rows down
        {col?}       (number) Columns right
        {offset?}    ({x?:number,y?:number}) Logical pixels right and down


sarthi.WindowFont                                          *sarthi.WindowFont*
    The fonts an external window's text is drawn with. Either left out is
    `guifont`'s. The window is as many of its own cells as its config says.

    Fields: ~
        {family?}  (string|string[]) One or more, in fallback order
        {size?}    (number) In points, like `guifont`'s `:h`


sarthi.WindowConfig                                      *sarthi.WindowConfig*

    Fields: ~
        {place?}    (sarthi.WindowPlace) External windows only
        {font?}     (sarthi.WindowFont) External windows only
        {shadow?}   (table) Its own |sarthi-shadow| values
        {outline?}  (table) External windows only: its own |sarthi-outline| values
        {corners?}  (table) External windows only: its own |sarthi-corners| values
        {padding?}  (table) External windows only: its own |sarthi-padding| values
        {scroll?}   (table) Its own |sarthi-scroll| values
